# 自包含执行计划

## 什么叫自包含

计划文档是这次工程的**唯一入口**。读它的人（和 agent）不需要打开任何其它计划文档就能开工。

**禁止**：
- 引用别的执行计划（"流程同 pr1-execution-plan.md"、"参考上次的 review 流程"）。
- 引用会话历史（"如上文讨论"、"按你刚才说的"）。
- 只给链接不给内容。需要的规则原文抄进来。

**允许并鼓励**：
- 引用仓库里的长期文档（`AGENTS.md`、`CLAUDE.md`、`docs/*`）——那是代码库事实，不是流程约定。
- 引用具体代码位置（`packages/api/src/router.ts:42`）。

## 文档骨架

用 `assets/execution-plan.template.md`。必备章节：

1. **背景与目标** — 为什么做，做完什么样。含明确的非目标。
2. **现状** — 已经读过的关键代码与结论，附文件路径。这是 agent 省 context 的最大来源，写实在的。
3. **总体设计** — 数据流 / 契约 / 关键类型。决策点要写清为什么选 A 不选 B。
4. **阶段拆分** — 用户已认可的那份，逐阶段展开到 commit + 完成判据。
5. **执行方式** — worktree 位置、分支名、阶段-workflow 映射、模型/effort、每阶段轮次、review 轮次、单 PR。
6. **Agent Briefing 原文** — 把 `references/04-agent-briefing.md` 全文抄进来，标明"每个 agent prompt 必须内联此段"。
7. **完成判据（整体）** — 全仓 check 命令清单 + agent-browser 验收路径清单。
8. **风险与假设** — 不确定的地方写成显式假设，别留空白。

## 语言与文体

- 简体中文散文，代码 / 路径 / 标识符 / 命令保持英文。
- 判据写成能直接粘进终端的命令，不写"确保测试通过"这种空话。
- 别写篇幅填充：没有冗余摘要、没有"综上所述"。

## 存放位置

跟仓库现有计划文档同目录同风格。没有既有目录就问用户，或放 `docs/`。文件名带明确 scope，不叫 `plan.md`。
