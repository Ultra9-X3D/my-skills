# 课程笔记更新与同步

在用户正在使用的 iCloud Obsidian 课程库中修改原笔记，让同一份文件通过 iCloud 同步到各设备。

## 先找对文件

- 在 Windows 上读取 `%APPDATA%/obsidian/obsidian.json`，核对库路径及 `open` 状态。helper 默认查找注册路径包含 `iCloud~md~obsidian`、名称为 `课程学习` 的 iCloud 库；其他库名或平台可用 `--vault` 显式指定经核对的同步目录。
- 以用户指定的课程和笔记为准。若通过桌面别名、软链接或 Windows 目录联接访问，先解析真实路径，不凭 cwd、同名文件或修改时间判断目标；不能假设某台电脑已经建立链接。
- 如果用户没有给笔记路径，可结合当前课程、库内 `.obsidian/workspace.json` 和实际 Markdown 内容定位。只有仍存在多个合理目标时才询问。
- 若找到尚未合并的独立副本，比较双方内容并保留新增记录。未经本次任务授权，不批量删库、改同步配置或重建链接。

## 读取与整理

1. 重新读取目标笔记及适用的 `AGENTS.md`。使用下方 helper 取得真实路径、当前 SHA-256 和 Obsidian 图片引用的位置。
2. 查看每张相关截图后再转写；图片通常在课程库的 `附件/` 中，也可能采用笔记相对路径。缺图、模糊公式或未记录的例题应明确标注，不凭空补写课堂内容。
3. 保持原有知识范围和学习顺序。将定义、公式、已有推导转为可编辑文字和 LaTeX，纠正笔误，解释直接影响理解的符号、积分方向、单位或适用条件。用户后来补的内容必须保留。
4. 图形有助于理解时保留图片和 Obsidian 链接。只含文字、公式的截图可用转写替换；混合图表可保留在折叠 callout 中，公式仍在正文转写。原附件不因转写而删除。
5. 沿用简体中文课堂笔记的口吻，解释先给直观含义。适当补充“做题从哪里入手”，但不把局部润色扩成一整本讲义。
6. 公式核对正负号、上下限、矢量/标量以及模型条件；源材料疑似有误时结合现有课件或教材核对。需要读 PPT/PDF 时再使用对应技能。

## 保存到唯一正文

helper 只依赖 Python 3.8+ 标准库。下面的脚本路径以此技能目录为基准，示例课程路径需替换为当前笔记。使用环境中可用的 Python；Windows 可用 `py -3 -X utf8`，其他平台可用 `python3` 并指定 `--vault`。

```powershell
py -3 -X utf8 scripts/note_sync.py inspect --note '26fall/大学物理下/笔记/真空中的静电场.md'
```

将润色结果先写到库外草稿文件，再把 inspect 返回的哈希作为提交条件：

```powershell
py -3 -X utf8 scripts/note_sync.py commit --note '26fall/大学物理下/笔记/真空中的静电场.md' --draft '<库外草稿的绝对路径>' --expected-sha256 '<inspect 返回的 sha256>'
```

- 默认从 Obsidian 注册表和 iCloud 目录定位课程库；`--vault` 可显式指定经核对的库，或用于隔离测试。
- helper 在写入前检查原文件哈希，备份到 `$CODEX_HOME/backups/course-notes`（未设置时为 `~/.codex/backups/course-notes`），原位写入并读回核对。哈希变化时重新读取、合并后再提交，不能自动覆盖用户刚输入的内容。
- 正文只写入解析后的 iCloud 文件；已有桌面链接会自然看到同一份内容，不再维护第二份正文。备份和草稿放在库外。
- 提交后核对重要章节、公式和保留图片的引用；再次 inspect 可检查图片路径及文件是否保持最新。

## 同步与交付的证据

确认文件位于 iCloud 课程库、保存成功且读回一致后，可报告“已保存到 iCloud 同步目录并读回核对”。这不等于已验证云端上传或 iPad 下载完成；只有取得相应设备或客户端的实际证据后，才能作出后一种声明。不要通过关闭同步、覆盖另一台设备或建立双向复制任务来催促同步。

交付时给出真实 iCloud 笔记的绝对路径链接，简要说明本次处理的内容。明确仍缺失的截图或模糊信息即可，无需输出检查日志。
