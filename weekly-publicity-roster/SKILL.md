# 宣传活动自动排班

把课表变成可核验的当周排班，并在飞书交付。用户通常只需提供带姓名的当周课表；由助手整理数据、运行脚本、发布和检查，不停在计划或模板，不要求用户自己制作 JSON。

## 固定业务规则

| 岗位 | 每天时段 | 人数 |
| --- | --- | --- |
| 深入活动宣传组 | 10:00—12:00、15:00—17:00 | 每小组恰好3人，每时段1—2小组 |
| 棚子宣传组 | 11:00—13:00、17:00—19:00、19:00—21:00 | 每时段至少2人，上限未限定 |

- 默认深入每时段1组、棚子每时段2人；先填满全周最低需求，人员充足或用户要求时再增加完整第二组或棚子人员。深入不足3人的小组标“未成组／缺人”，不能声称满足要求。
- 同一个人不能承担任何时间重叠的班次，尤其10:00—12:00与11:00—13:00。尊重课程、岗位限制、明确不能值班时段和指定换人要求。
- 没有每人最多几班、必须负责人搭配、禁止连班等额外硬规则。均衡工时、分散晚班和避免一天过多班次属于优化偏好，不擅自变成硬限制。
- 课程前后默认预留10分钟通行时间，属于可调整的参数，在排班说明中披露。

## 1. 确定本次范围

默认用户当前时区的本周周一至周日，含周末；指定日期优先。结果写绝对日期，不复用历史教学周。周中安排全周时，过去时段标“历史日期的安排参考”，不能推断已实际出勤；优先展示尚未开始的班次。

新上传课表的名单视作本次参与人员；没有岗位意愿时默认两种岗位均可，记录这一假设。同时有报名表时合并两批人员，填写姓名表示该报名时段可用。按明确身份去重，不只凭同名合并。

[资料来源绑定](references/known-context.md) 说明如何沿用用户提供的飞书资料。旧名单、旧报名和旧课表不自动视为本周有效。只提供课表时也要完成排班，不强制要求第二张表。

仅对影响可靠性的缺项提问，例如课表无法对应姓名、日期或单双周无法判断、节次没有钟点且找不到可靠作息表。关键问题一次问清，同时处理其他人员。不要重复询问已确认规则或例行要求发布确认。

## 2. 逐人核验课表

查看实际图片／PDF页面，OCR仅辅助。识别日期、教学周、单双周、课程周次范围、钟点、周末补课和手写备注。区分灰色“非本周”课程与本周有效课程；没有钟点时核实该校当前作息，不凭常见节次猜测。

完整显示且属于目标周的空白区域支持“课表无冲突”；裁切缺失、其他周截图、模糊文字或无法判断周次的区域不等于空闲。课表无冲突也不等于本人已确认。保留证据类型：课表推定／报名覆盖／相邻报名推定／本人确认。

按 [数据格式](references/input-schema.md) 整理临时 `work/roster-input.json`，使用具体日期，保存来源定位、可见范围、课程与明确不可用时段。看不到的日期不创建可用记录。看板只放必要信息，不传播完整私人课表截图。

## 3. 排班与验证

运行随技能提供的 `scripts/roster.py solve`。脚本负责约束与分配，课表识别由助手完成，无需第三方 Python 包。

优先级：遵守硬限制 → 尽量填满最低需求 → 减少待确认安排 → 均衡工时、每日负担与晚班。脚本为多轮启发式搜索，不声称数学最优或证明缺口无解。存在缺口时复查候选和换班链，必要时增加搜索轮数或使用可用优化器，再如实报告。

用户已允许参考相邻报名时段作“待本人确认”安排。记录未覆盖的具体时间，不能标成全程已确认。脚本默认相邻间隔最多30分钟、未覆盖总时长最多60分钟，这些是保守可调整参数；扩大推定须有证据并披露。推定不能覆盖已知课程、明确不能值班或未知的课表区域。

运行 `scripts/roster.py validate` 校验生成或人工修改的方案。核查身份、岗位、证据、课程缓冲、重叠、日期、人数、待确认标记、缺口和显式限制。缺人可作为带缺口方案交付，不能写成全覆盖；扩编须调整人数需求后重排、重验。

## 4. 飞书交付

使用当前 `lark-base` 技能和工具，电子表格另用 `lark-sheets`。先读 [飞书交付与核验](references/feishu-delivery.md)。默认完成：

1. **课程式总览**：列为周一至周日及日期，行为五个岗位时段，每格显示姓名、小组编号、待确认和缺口。
2. **班次明细**：每日期与岗位时段一条，含起止时间、应到、已排、缺口、人员和待确认原因。
3. **个人安排**：一人一班一条，可按人分组，含证据与需确认时间。
4. **人员与课表核验**：总工时、班次数、资料有效性与未安排原因。
5. **可视化页面**：每天值班卡片、已排人次、缺口、待确认和工作量分布，以及总览、明细入口。提供周日历、待确认、缺口、近期班次视图。

新周保留历史，同周优先更新已有交付，避免多个矛盾版本。实际资源ID和链接保存在本次工作目录，不把未来记录ID硬编码到技能。正常创建／更新排班已属任务授权；发私信、群通知和扩大分享权限不在默认范围。

## 5. 换人补班与完成标准

用户删除某班人员时，以该日期班次为范围补人，先保留其他有效安排。把保留安排放入 `locked`，被移除者放入该班 `exclusions`，防止选回。锁定造成缺口时寻找必要的最小调换；一次换人不能变成永久排除。

更新前实时读取飞书，识别用户编辑。已知主动修改直接遵循；来源不明的矛盾才询问。同步总览、明细、个人安排、统计和每日卡片。文本快照需重生成，没有实际配置自动化就不能声称视图实时互相同步。

分页回读全部记录，重验总人次、缺口、待确认、工时和各页面姓名一致；实际查看总览与看板，核查换行、日期顺序、日历起止时间、保存状态和筛选实际结果。无法访问飞书时先交付本地可审阅方案，明确尚未发布和阻碍，不编造链接。

最终简短提供飞书入口、目标周、覆盖情况及缺口／待确认事项。不能把待确认安排说成已经联系或获得同意。
